# 给同事开通知识库

两条路径：管理员在后台开通账号，同事在客户端填三项就能用。

## 管理员：三步

1. 打开后台 **成员与权限 → 新建成员**，填姓名（邮箱可选），勾上他能看的知识库，需要临时授权就填到期时间。
2. 点 **创建并生成令牌**。令牌只显示这一次，关掉就看不到了——服务端只存哈希，没有"再查看一次"的接口。
3. 点 **复制接入说明**，把那段话原样发给同事。里面已经带好地址和他的令牌，不用你手打。

人走了点 **停用账号**（令牌立刻失效，比逐个撤库彻底）；令牌丢了点 **重置令牌**（旧的立刻作废）。

## 同事：在客户端里填三项

在支持 MCP 的客户端里新建一个「自定义连接器 / MCP 服务器」：

| 字段 | 填什么 |
|---|---|
| 传输类型 | `HTTP` |
| 服务器 URL | 管理员给的地址，形如 `http://…/mcp` |
| 自定义 Header | `Authorization` = `Bearer 你的令牌` |

几个常见客户端的位置：

- **Cursor**：`.cursor/mcp.json` 里加 `{"mcpServers": {"knowledge": {"url": "…/mcp", "headers": {"Authorization": "Bearer …"}}}}`
- **Cherry Studio / ChatWise**：设置 → MCP 服务器 → 添加 → 类型选 HTTP，把 URL 和 Header 填进去
- **Claude Desktop**：它不直接支持 HTTP，要用 `npx -y mcp-remote <地址> --header "Authorization: Bearer …"` 包一层

连上后可以问「用 knowledge 查：<问题>，附上原文」。可用工具只有两个，都是只读：`search_knowledge` 查内容，`get_knowledge_reference` 取原文片段。

## 查不到内容时按这个顺序排查

| 现象 | 原因 |
|---|---|
| 一直转圈、最后超时 | 安全组没放行他的来源 IP，或者地址、端口写错了 |
| 立刻报 403，页面带 nginx 字样 | 到了服务器，但来源 IP 不在白名单里（只有管理员开了来源限制才会出现） |
| 页面显示 Cloudflare 的 `1033` 或 `502` | 服务器上的隧道断了，找管理员重启 `cloudflared` |
| `401` 或提示令牌无效 | 令牌没粘全（通常漏了尾部），或者账号被停用了 |
| 能连上但结果为空 | 他要查的库没勾给他，或者那个库还没发布过内容 |
| 之前能查、现在查不到 | 授权被撤了、到期了，或者文档被下架 |

授权和停用都是**立刻生效**的：服务端每次查询都重新算一次可见范围，不需要重启任何服务，也不需要同事重连。
